# Proposal: Non-Interactive Simplification

**Date:** 2026-07-11
**Status:** Accepted
**Author:** haolin + ai_research

## Motivation

cmdguard was designed with an interactive confirmation layer (TTY prompts with
timeouts) for human operators. In practice, the primary users are AI agents
running via QwenPaw -- nobody sits at a terminal pressing `y`. The interactive
layer adds ~300 lines of code, a config section (`[guard]`), two env vars, and
a `GuardConfig` struct, none of which serve the actual use case.

This proposal eliminates the interactive layer entirely and simplifies the
protection model to its essence: **reject, guard, or allow**.

## Changes

### 1. Bypass format: 4-segment → 3-segment

**Before:** `--bypass=<host>/<platform>/<agent>/<task>` (4 segments)

**After:** `--bypass=<platform>/<agent>/<task>` (3 segments)

#### Why drop the host/IP segment?

The host segment was originally intended to identify the source machine. But
cmdguard wraps local `rm`/`mv`/chmod` -- it always runs on the machine whose
files are being operated on. The audit log is on that machine. Recording the
local NIC IP adds zero audit value.

Auto-filling from `SSH_CLIENT` was considered (to capture remote caller IP),
but rejected: it adds "source inference" complexity to a file-protection tool,
and fails for non-SSH agent invocation paths.

#### All three segments are mandatory and manually written

No environment variables for auto-fill. The caller (agent or human) always
writes the full 3-segment identifier:

```
# Agent
--bypass=qwenpaw/ai_research/cleanup-vault

# Human
--bypass=manual/haolin/remove-old-logs
```

`ValidateBypass` changes from 4-segment to 3-segment validation. The
minimum total length drops from 12 to 10 characters. Placeholder tokens
list drops `"host"` and adds nothing.

### 2. Kill the TTY interaction layer

**Deleted code:**

| Item | Location |
|------|----------|
| `readLineWithTimeout()` | `guard.go` |
| `isTerminal()` | `guard.go` |
| `emitNonTTYRejection()` | `guard.go` |
| `emitNonTTYRejectionTimeout()` | `guard.go` |
| `nonTTYReason` type + constants | `guard.go` |
| First/second confirm interaction blocks (~80 lines) | `guard.go` |
| `bufio` / `time` imports | `guard.go` |

### 3. Protection levels: 4 → 3

**Before:**

| Level | Behavior |
|-------|----------|
| `reject` | Always rejected |
| `confirm_double` | Interactive double-confirm → backup → execute |
| `confirm` | Interactive single-confirm → backup → execute |
| `warn` | Print warning → execute (no backup, no bypass needed) |
| `(allow)` | Execute directly |

**After:**

| Level | Behavior |
|-------|----------|
| `reject` | Always rejected, even with --bypass. Logged, not backed up. |
| `guarded` | Without --bypass: rejected + logged. With valid --bypass: backup → log → execute. |
| `allow` | Execute directly. Logged. |

`confirm` and `confirm_double` merge into `guarded`. `warn` is removed
(it was unused in default config and has no security meaning in
non-interactive mode).

### 4. GuardResult.Action: 5 values → 3 values

```go
// Before
"reject", "confirm_double", "confirm", "warn", "allow"

// After
"reject", "guarded", "allow"
```

Legacy level strings (`confirm`, `confirm_double`, `warn`) are kept as
constants for log-reading compatibility (`undo`, `list` subcommands may
encounter old log entries).

### 5. Delete env vars and GuardConfig

**Deleted:**

| Item | File |
|------|------|
| `EnvAgentMode` (`CMDGUARD_AGENT_MODE`) | `env.go` |
| `EnvNonInteractive` (`CMDGUARD_NONINTERACTIVE`) | `env.go` |
| `IsAgentMode()` function | `env.go` |
| `GuardConfig` struct | `config.go` |
| `[guard]` config section | `config.go` + all docs + example toml |

The entire `[guard]` config section (`confirm_timeout`,
`confirm_double_timeout`, `agent_mode`) is gone. There is nothing to
configure -- behavior is fully determined by the 3-level protection model.

### 6. Wrapper script simplification

Wrapper scripts generated by `cmdguard init` no longer set any env vars.
They simply forward `rm`/`mv`/`chmod` calls to the cmdguard binary.

### 7. msg/guard.go slim down

**Deleted message constants (~18):**

- All confirm/timeout messages: `ConfirmHint`, `ConfirmDoubleHint`,
  `ConfirmPrompt`, `ConfirmDoublePrompt2`, `ConfirmCancelled`,
  `ConfirmTimeoutMsg`, `ConfirmTimeoutDisabled`, `ConfirmTimeoutLogMsg`,
  `ConfirmCancelledMsg`, `ConfirmDoubleCancelledMsg`
- All agent-mode messages: `GuardAgentModeRejected`, `GuardAgentModeMsg`,
  `GuardAgentBackupFailed`, `GuardNonTTYRejected`, `GuardNonTTYMsg`
- `LevelActions` map (removed entirely)

**New message constants:**

- `GuardNoBypassRejected` -- replaces `GuardNonTTYRejected` +
  `GuardAgentModeRejected`
- `GuardNoBypassMsg` -- replaces `GuardNonTTYMsg` + `GuardAgentModeMsg`
- `GuardBackupFailed` -- replaces `GuardAgentBackupFailed`

### 8. reject: log but don't backup

A reject is an audit event ("someone tried to touch a protected path and was
denied"). It is always logged. Since the operation is not executed, there is
nothing to back up.

### 9. Backup failure: always fatal

**Before:** In agent mode, backup failure = exit 1. In normal mode, backup
failure = warning + proceed.

**After:** Backup failure is always fatal. The undo safety net is broken;
proceeding without rollback capability is irresponsible regardless of
whether the caller is an agent or a human.

```
[cmdguard] BACKUP FAILED: <path>: <error>
[cmdguard] backup failed, aborting (undo safety net broken)
exit 1
```

Log entry: `action=reject, message=backup_failed: <path>: <error>`

### Migration

- **Config files:** Users with `[guard]` sections in `config.toml` will
  see those keys silently ignored (TOML decoder skips unknown fields).
  No breakage, but `cmdguard config` output will no longer show them.
- **Existing wrappers:** Still work -- they call the cmdguard binary
  which now ignores `CMDGUARD_AGENT_MODE`/`CMDGUARD_NONINTERACTIVE`.
  `cmdguard init --force` will regenerate clean wrappers.
- **Existing bypass identifiers:** 4-segment identifiers will be rejected
  by the new 3-segment validator. Agents must update their `--bypass`
  values.
- **Log entries:** Old log entries with `action=confirm`/`confirm_double`/
  `warn` remain readable by `list` and `undo` (legacy constants retained).

### Version

Major simplification, breaking change for bypass format → version bump
to v0.14.0 (or whatever the next minor is after current HEAD).

## Rejected alternatives

### Auto-fill bypass segments from env vars

Proposed: cmdguard reads `CMDGUARD_CALLER` (platform) and
`CMDGUARD_CALLER_ID` (agent) from env vars set by QwenPaw, auto-filling
the first two segments so the caller only writes the task.

**Rejected because:**
- Adds two new env vars (complexity)
- IP segment auto-fill from NIC was meaningless (see §1)
- `CMDGUARD_CALLER`/`CMDGUARD_CALLER_ID` are audit-only env vars that
  don't affect behavior -- but they still add a contract surface
- User decided: "别搞环境变量了，都是必须写吧"

### Keep IP segment, read from SSH_CLIENT

Proposed: First segment = caller source IP, read from `SSH_CLIENT`/
`SSH_CONNECTION` env vars. `127.0.0.1` for local sessions.

**Rejected because:**
- Adds "source inference" responsibility to a file-protection tool
- Fails for non-SSH agent paths (API → local shell)
- The machine identity is already implicit in the log file location
